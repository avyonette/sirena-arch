\section{Introduction}
This document complements the \verb|SiERNA| computer architecture by specifications for the \gls{CPU}. It is to be used as a reference for both software and hardware developers for functions and working details of the \gls{CPU}.

\subsection{Architectural details}
\begin{itemize}
	\item \emph{Little-endian} memory model
	\item \emph{Paging} for memory separation
	\item \emph{\acrshort{MMIO}} for device I/O
	\item \emph{2-level} protection domain
	\item \emph{Extensions} for optional features and additional instruction sets
\end{itemize}

\section{Registers}

The SiERNA architecture, similarily to the TMS9900, does not store general-purpose registers on the CPU, but rather a \emph{frame pointer} that points to the address in \emph{system RAM} of the current \emph{register frame} for the executing context.

A \emph{register frame} refers to a (virtual) structure in RAM of 128 bytes (1024 bits) in length that stores 32 4-byte values total:

\textbf{IMPORTANT: Every \emph{register frame} used by the \emph{target program} MUST be word-aligned and zeroed before first use.} \\

\textbf{IMPORTANT: Any used \emph{register frame} MUST be located inside the physical memory region that maps \emph{system RAM}. For more information see \ref{mm:PML}.}\\

Registers are categorised into two categories:
\begin{itemize}
	\item \textbf{Global} registers are stored directly on the CPU and their values persist between frame changes
	\item \textbf{Local} registers are stored in the \emph{register frame} and their address and/or value depends on the current \emph{frame pointer}
\end{itemize}

\subsection{Pointer registers}
\subsubsection{(0x1D) rfp - frame pointer}
{\small \textit{Availability: Global}}

{\small \textit{Write-restricted}}

Stores the physical address to the current \emph{register frame}. It must point to an address within the \emph{system RAM} (See \ref{mm:PML}); otherwise, the CPU raises a \hyperref[ir:IOP]{\textbf{\#IOP}} on write.

\subsubsection{(0x1E) rrap - interrupt routine array pointer}
{\small \textit{Availability: Global}}

{\small \textit{Write-restricted}}

Stores the physical address to the current \hyperref[ir:ARRAY]{Interrupt Routine Array}. Set by the supervisor to indicate which IRA the CPU should use for interrupt handling

\subsubsection{(0x13) rlfp - last frame pointer}
{\small \textit{Availability: Local}}

{\small \textit{Read-only}}

Stores the physical address to the previous \emph{register frame}. Used when returning from interrupt routines. \hyperref[ir:IOP]{\textbf{\#IOP}} is raised on a write attempt.

\subsubsection{(0x10) rip - instruction pointer}
{\small \textit{Availability: Local}}

Stores the address of the currently executing instruction

\subsubsection{(0x11) rtp - procedure tail pointer}
{\small \textit{Availability: Local}}

Stores the address of the instruction that called the current procedure

\subsubsection{(0x12) rsp - stack pointer}
{\small \textit{Availability: Local}}

Stores the address of the current stack frame

\subsubsection{(0x14) rpdp - page directory pointer}
{\small \textit{Availability: Local}}

{\small \textit{Write-restricted}}

Stores the physical address of the level-0 page directory structure. If it points to 0, paging is disabled.

\section{Memory access} \label{ma}
All memory I/O requires the target address to be aligned to the boundary of the type that is being requested.

This means that word I/O requires the address to be aligned to \verb|0x4|, half-word I/O requires the address to be aligned to \verb|0x2|, and byte I/O is unrestricted (\verb|0x1| alignment).

On incorrect address alignment the MMU raises a \textbf{\hyperref[ir:MAE]{\#MAE}}.

\subsection{Boot-up Late Initialisation Program}
The function of the \acrshort{BLIP} is final hardware and device initialisation before loading and handing over control to the \emph{target program}. How the target program is discovered and loaded is up to the specific implementation.

\section{Operation cycle}
The CPU operates at with standard fetch$\to$decode$\to$execute cycle. By the end of a single cycle, the CPU must advance the \emph{instruction pointer} by a single word for any executed instruction that does not explicitly set the \emph{instruction pointer}.

\section{Interrupts}
Interrupts are handled by the CPU after every execute cycle of a single instruction. The CPU checks if any interrupts were raised after executing the instruction and, if so, checks and picks the correct \hyperref[ir:HANDLER]{Interrupt Routine Handler} from the current \hyperref[ir:ARRAY]{Interrupt Routine Array} to handle the raised interrupt, switching to the \emph{register frame} specified for the handler and filling in/out registers if necessary.

If the \verb|enable| bit of the IRA entry is not set, the interrupt stops being handed over to be handled in software, but the exact behaviour depends on the type of the raised interrupt.

If the \verb|rrap| register is set to 0, all interrupts except \emph{faults}, which immediately prompt a CPU reset, are ignored. \\

There are three types of interrupts:

\begin{table}[H]
	\centering
	%\resizebox{\linewidth}{!}
	{
		\begin{tabular}{|c|c|c|}
\hline
Type & Recoverable & Unhandled pauses execution \\
\hline
Signal & \cmark & \xmark \\
\hline
Trap & \cmark & \cmark \\
\hline
Fault & \xmark & \cmark \\
\hline
		\end{tabular}
	}
\end{table}

\begin{itemize}
	\item \emph{Signal} interrupts do not pause execution and do not have to be explicitly handled in any way. This type of interrupt is recommended for general hardware-software communication.
	\item Raised \emph{trap} interrupts are most commonly recoverable errors and will pause execution of the frame that the trap occurred in if no valid IRH was found to handle the raised interrupt.
	\item Raised \emph{fault} interrupts are non-recoverable and reset the CPU upon existing from the IRH or if no valid handler was found. These cannot be raised manually from software.
\end{itemize}

\subsection{Interrupt Routine Handler} \label{ir:HANDLER}
Interrupt Routine Handlers (IRH) are \emph{user-defined} \emph{level-1} procedures that respond to a specific interrupt raised by the CPU. IRs have their own \emph{register frame} and can access the previous \emph{register frame} via its address located in the \verb|rlfp| register.

IRHs can exit at any time and resume execution by calling \verb|reti|. For non-recoverable interrupts this will result in the CPU being reset.

\subsection{User-defined interrupts}
Any ID in the \emph{user-defined} range (See \ref{ir:list}) can be used for custom interrupts. These can only be of the \textbf{signal} type.

\section{Memory management}
\subsection{Paging}
The SiERNA architecture utilises \emph{paging} as its technique for memory protection and virtual address space mapping. A single page spans \textbf{4 KiB} (\verb|0x1000|) of physical memory.

The page table is a 3-level nested structure; the full 32-bit virtual address space (0x0000 0000 - 0xFFFF FFFF) is encapsulated by a level-0 page directory which contains 256 entries, each pointing to a level-1 page directory. A level-1 page directory contains 256 entries, each pointing to a page table (or 0). Every page table entry (page descriptor) then describes the page as well as its physical address. This allows for mapping the entire address range without unnecessarily wasting too much memory for paging structures in situations that do not need the entire address range mapped.

\subsection{Virtual memory}
The position (offset/index) of a page descriptor within the page directory as a whole determines the virtual address that gets mapped to the specific physical address that the page descriptor contains.

For example, the virtual address \verb|0xABCDE000| would need a page descriptor at the 15th (\verb|(0xABCDE000 >> 12) & 15 = 14|) position of the page table located at the 206th (\verb|(0xABCDE000 >> 16) & 255 = 205|) position of a level-1 page directory, which would be addressed in the 172th (\verb|0xABCDE000 >> 24 = 171|) position of the level-0 page directory.

This also translates to the last 8 bits (\verb|0xFF000000|) of the address indicating the level-1 page directory index, the previous 8 bits (\verb|0x00FF0000|) indicating the level-1 page directory index, and the previous 4 bits (\verb|0x0000F000|) indicating the page table index, with the last 12 bits being the in-page address offset as pages are aligned to (\verb|0x1000|).

\subsection{Access protection}
The nature of paging implicitly provides memory access protection features. Since, unless explicitly overriden or sharing physical pages between contexts, each context has its own virtual address space and virtual-physical address map, a malicious context cannot access memory of other contexts.

\subsection{Memory Management Unit}
The MMU is handles memory I/O operations and address routing.

\begin{itemize}
	\item For \emph{paging}, the MMU is responsible for translating virtual addresses to physical addresses
	\item For \emph{I/O}, the MMU takes a requested physical address and acts like a \emph{multiplexer} to correctly route the I/O operation in accordance with the \hyperref[mm:PML]{physical memory layout}, performing the requested operation
\end{itemize}

\section{Protection domains}
There exist two privilege levels:
\begin{itemize}
	\item Level 0, \emph{user} level, is dedicated for regular user applications
	\item Level 1, \emph{supervisor} level, is dedicated for the \emph{target program} or OS kernel
\end{itemize}

along with three primary mechanisms contributing to system/cross-program security:
\begin{enumerate}
	\item Some registers having restricted read-only access for level-0
	\item Non-register I/O access to some memory regions being restricted to level-1
	\item Per-page permissions
\end{enumerate}

Enforcing privilege levels is the job of the CPU. This happens at five stages:
\begin{enumerate}
	\item When writing to \emph{rpl}, the CU checks if the requested privilege level is valid. If not, it raises a \hyperref[ir:GPE]{\textbf{\#GPE}}
	\item When writing a register, the CU checks the current privilege level and, if it isn't level 1 and the target register is write-restricted, raises a \hyperref[ir:GPE]{\textbf{\#GPE}}
	\item Upon receiving a \verb|tavp| operation, the MMU reads the current privilege level as well as the requested page's privilege level, and raises a \hyperref[ir:GPE]{\textbf{\#GPE}} if they don't match
	\item Upon receiving a \verb|tavp| operation, the MMU checks the provided purpose (R/W/X), matches it with the requested page's permissions, and if they don't match it raises a \hyperref[ir:GPE]{\textbf{\#GPE}}
	\item Upon receiving a \verb|mread*| or \verb|mwrite*| operation, the MMU checks if the provided physical address is in a restricted range. If it is, and the current privilege level is not level 1, it raises a \hyperref[ir:GPE]{\textbf{\#GPE}}
\end{enumerate}

\subsection{Protection level transfer}
A transfer between protection level for the current \emph{frame} can be performed at at any time by the \emph{supervisor} by writing to the \verb|rpl| register or for any frame by writing to its memory directly.
