\section{Registers}

The SyrENA architecture, similarily to the TMS9900, does not store general-purpose registers on the CPU, but rather a \emph{frame pointer} that points to the address in register RAM of the current \emph{register frame} for the executing context.

A \emph{register frame} refers to a (virtual) structure in RAM of 128 bytes (1024 bits) in length that stores 32 4-byte values total:

Registers are categorised into two categories:
\begin{itemize}
	\item \textbf{Global} registers are stored directly on the CPU and their values persist between frame changes
	\item \textbf{Local} registers are stored in the \emph{register frame} and their address and/or value depends on the current \emph{frame pointer}
\end{itemize}

\section{Interrupts}
Interrupts are handled by the CPU after every execute cycle of a single instruction. The CPU checks if any interrupts were raised after executing the instruction and, if so, checks and picks the correct \hyperref[ir:HANDLER]{Interrupt Routine Handler} from the current \hyperref[ir:ARRAY]{Interrupt Routine Array} to handle the raised interrupt.

If the \verb|enable| bit of the IRA entry is not set, the interrupt is not handled in software, but the exact behaviour depends on the type of the raised interrupt. \\

There are three types of interrupts:

\begin{table}[H]
	\centering
	%\resizebox{\linewidth}{!}
	{
		\begin{tabular}{|c|c|c|c|c|}
\hline
Type & SW & HW & Recoverable & Pauses execution \\
\hline
Signal & \cmark & \cmark & \cmark & \xmark \\
\hline
Trap & \cmark & \cmark & \cmark & \cmark \\
\hline
Fault & \xmark & \cmark & \xmark & \cmark \\
\hline
		\end{tabular}
	}
\end{table}

\begin{itemize}
	\item \emph{Signal} interrupts do not pause execution and do not have to be explicitly handled in any way. This type of interrupt is recommended for general hardware-software communication.
	\item Raised \emph{trap} interrupts are most commonly recoverable errors and will pause execution of the frame that the trap occurred in if no valid IRH was found to handle the raised interrupt.
	\item Raised \emph{fault} interrupts are non-recoverable and reset the CPU upon existing from the IRH or if no valid handler was found. These cannot be raised manually from software.
\end{itemize}

Upon startup the \emph{bootup late initialisation program} sets the \verb|rrap| register to a new empty, zeroed IRA. Upon taking control, the \emph{target program} should allocate its own IRA, filling it with whatever entries are necessary to handle wanted interrupts, and set the value of \verb|rrap| to the address of said IRA.

\subsection{Interrupt Routine Handler} \label{ir:HANDLER}
Interrupt Routine Handlers (IRH) are user-defined procedures that respond to a specific interrupt raised by the CPU. IRs have their own \emph{register frame} and can access the previous \emph{register frame} via its address located in the \verb|rlfp| register.

IRHs can exit at any time and resume execution by calling \verb|reti|. For non-recoverable interrupts this will result in the CPU being reset.

\section{Memory management}
\subsection{Paging}
The SiERNA architecture utilises \emph{paging} as its technique for memory protection and virtual address space mapping. A single page spans \textbf{4 KiB} (\verb|0x1000|) of physical memory.

The page table is a 3-level nested structure; the full 32-bit virtual address space (0x0000 0000 - 0xFFFF FFFF) is encapsulated by a level-0 page directory which contains 256 entries, each pointing to a level-1 page directory (or 0). A level-1 page directory contains 256 entries, each pointing to a page table (or 0). Every page table entry (page descriptor) then describes the page as well as its physical address. This allows for mapping the entire address range without unnecessarily wasting too much memory for paging structures in situations that do not need the entire address range mapped.

\subsubsection{Setting up paging}
On early initialisation, the \emph{bootup late initialisation program} sets up an identity map for the low memory region (\verb|0x00000000-0x00010000|). After the \emph{target program} takes over it should set up its own page directory structure according to its needs and point its \verb|rpdp| register to the physical address of the level-0 page directory.

\subsection{Virtual memory}
The position (offset/index) of a page descriptor within the page directory as a whole determines the virtual address that gets mapped to the specific physical address that the page descriptor contains.

For example, the virtual address \verb|0xABCDE000| would need a page descriptor at the 15th (\verb|(0xABCDE000 >> 12) & 15 = 14|) position of the page table located at the 206th (\verb|(0xABCDE000 >> 16) & 255 = 205|) position of a level-1 page directory, which would be addressed in the 172th (\verb|0xABCDE000 >> 24 = 171|) position of the level-0 page directory.

This also translates to the last 8 bits (\verb|0xFF000000|) of the address indicating the level-1 page directory index, the previous 8 bits (\verb|0x00FF0000|) indicating the level-1 page directory index, and the previous 4 bits (\verb|0x0000F000|) indicating the page table index, with the last 12 bits being the in-page address offset as pages are aligned to (\verb|0x1000|).

\subsection{Access protection}
The nature of paging implicitly provides memory access protection features. Since, unless explicitly overriden or sharing physical pages between contexts, each context has its own virtual address space and virtual-physical address map, a malicious context cannot access memory of other contexts.
